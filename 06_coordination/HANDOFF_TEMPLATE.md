# Handoff template

Use this when another person or session needs an identified task and delivery.
A single message can contain the whole handoff. Split message, task, inputs, and
receipt only when their size or access boundaries justify it.

Replace all `REPLACE_` fields. A prepared handoff is not proof of delivery,
activation, or authorization. See the [worked coordination example](../examples/coordination_and_publication/README.md).

## Message and activation

- Handoff ID/revision: REPLACE_HANDOFF_ID_AND_REVISION
- Authoring session (`source_session`): REPLACE_ACTUAL_AUTHOR
- Date: REPLACE_DATE
- Recipient: REPLACE_RECIPIENT
- Delivery route/owner: REPLACE_PERSON_OR_AUTHORIZED_MECHANISM
- Task and applicable instructions: REPLACE_EXACT_REFERENCES
- Input/delivery versions: REPLACE_EXACT_VERSIONS_AND_PATHS
- Activation condition: REPLACE_EVENT_AND_REQUIRED_INPUTS
- If a prerequisite is missing: REPLACE_RECOVERY_ROUTE

Do not substitute an unspecified “latest” delivery for an identified package.
Complete useful independent preparation only within the assignment.

## Outcome and ownership

**Required outcome:** REPLACE_CONCRETE_OUTCOME

| Situation | Assigned session owns | Return to decision owner when |
| --- | --- | --- |
| Routine correction within the task | REPLACE_ALLOWED_CORRECTIONS | REPLACE_BOUNDARY |
| Disputed evidence or new technical claim | REPLACE_ALLOWED_INVESTIGATION | REPLACE_MATERIAL_EXCEPTION |
| Completed local delivery | REPLACE_REVIEW_OR_PREPARATION | REPLACE_NEXT_GATE |
| Conflict with another session's work | REPLACE_NONINTERRUPTING_ROUTE | REPLACE_DECISION_NEEDED |

Do not require another approval for work already authorized. Name the material
decisions that remain reserved. Do not inspect or interrupt other sessions unless
the actual assignment authorizes that coordination.

## Phases, if needed

| Phase | Required input/activation | Output and completion evidence | Next event |
| --- | --- | --- | --- |
| REPLACE_PHASE | REPLACE_PREREQUISITE | REPLACE_OUTPUT_AND_CHECK | REPLACE_RETURN_OR_NEXT_AUTHORIZED_ACTION |

Preparing the next message does not send it. A phase label does not activate the
next phase. Record the actual return/delivery event if it matters.

## Checks and correction route

- Acceptance criteria: REPLACE_BEHAVIOR_OR_CLAIMS_AND_EVIDENCE
- Verification mode: REPLACE_STATIC_SAVED_EVIDENCE_OR_AUTHORIZED_EXECUTION
- Prior authorship/involvement: REPLACE_DISCLOSURE
- Routine correction route and allowance: REPLACE_ROUTE_AND_LIMIT
- Writable output paths: REPLACE_OUTPUT_PATHS
- Resources and stopping point: REPLACE_LIMITS_AND_STOP

For independent behavioral review, specify whether the reviewer must record
expected results before seeing the author's implementation and which helper
lineage is permitted. A separate session name alone does not establish
independence.

Return the identified delivery, actual checks, limits, unresolved decisions,
and next owner. For documentary work, use a [claim/evidence map](CLAIM_EVIDENCE_TEMPLATE.md)
when several conclusions or destination states need tracking.
