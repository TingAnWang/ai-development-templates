# Filled handoff example: local diagnostic summary

**Status:** abbreviated adaptation of the November 5 coordination charter,
not an active message or assignment.

**Adaptation author:** repository maintainer with AI drafting assistance  
**Prepared:** November 10, 2026  
**Recipient:** documentation coordinator  
**Delivery route:** user carries the prepared handoff between sessions.

## Inputs and outcome

Use the identified closed diagnostic, saved-answer comparison, their reviews,
and the owner's acceptance decision. The [claim map](CLAIM_MAP.md) illustrates
the required distinctions; the original frozen source package is not included
in this repository.

Prepare one source-backed local summary increment and a concrete publication
proposal. Keep technical result, review, acceptance, and publication states
separate. Do not rerun the diagnostic to write the summary.

## Ownership

Own routine source reconciliation, the local-author handoff, and documentary
review of the returned summary. Resolve wording within the approved claims.
Preserve source identity, author, cutoff, and qualifications.

The source charter used a finite documentary correction route. A new assignment
must specify its own allowance rather than infer it from this abbreviated copy.
Return material exceptions, new technical claims, and expanded source scope
to the owner with concrete alternatives.

## Phases

1. **Phase A:** prepare the bounded local-author handoff and return it to the user.
2. **Phase B:** resume when the user returns that author's sealed delivery.
   Verify the identified package and review it against the assignment.
3. **Proposal:** prepare the concrete publication change, prerequisites,
   verification plan, and unresolved decision.

If the sealed delivery is missing, identify that prerequisite and return the
recovery request through the user. Do not guess a delivery from unrelated files
or inspect another session to obtain it.

## Return and stop

Return the local summary's disposition, claim map, review evidence, remaining
qualifications, and publication proposal. Stop before the separately scoped
external publication. In this historical task, preparing a proposal did not
authorize sending messages, dispatching sessions, or mutating destinations.
