# Worked example: coordinate a summary through a publication hold

Companion to **The Decisions Behind My Multi-Agent Workflow**.
Read the [handoff](HANDOFF.md) and [claim map](CLAIM_MAP.md) for filled adaptations.
The reusable [handoff](../../06_coordination/HANDOFF_TEMPLATE.md) and
[claim/evidence map](../../06_coordination/CLAIM_EVIDENCE_TEMPLATE.md) work without
Notion, a database, or automated dispatch.

**Provenance:** prepared with AI drafting assistance from the author's saved
November 5 coordination charter, claim map and documentary review, November 6
publication-hold decision, and approved article draft. Factual cutoff:
November 10, 2026. These are documentary case-study reports. Original private
source packages and destination captures are not included; no publication
operation or experiment is reproduced here.

## Give the coordinator a complete local responsibility

The charter said:

> You own routine source reconciliation, local-writer handoff and documentary review. Do not send each wording change back for another main audit.

The coordinator owned a local cycle: reconcile sources, prepare the author's
bounded assignment, review the returned summary, and prepare a concrete
publication proposal. The user connected stages. Material exceptions and
publication remained separate decisions.

| Situation | Coordinator's assigned responsibility | Boundary |
| --- | --- | --- |
| Routine wording/source reconciliation | Resolve it within approved claims | No extra routine main audit |
| Local summary needs documentary correction | Use the named finite correction route through the user | Return if that allowance or scope is exceeded |
| New technical claim or expanded source scope | Preserve finding and alternatives | Owner decides changed basis |
| Local summary passes review | Prepare concrete publication proposal | Does not itself authorize publication |
| Conflict with another session | Report or queue through the user | No inspection or interruption of that session |

A “pure reviewer” remains a different role: it reports findings without taking
over the implementation. The continuing session specification and current task
determine which responsibility applies.

## Identify what activates the next phase

Phase A stopped at the prepared author handoff. Phase B required the user's
return of that author's identified, sealed package. A prepared message was not
automatic dispatch.

In another review assignment, the review message arrived without the writer's
sealed result. The reviewer identified the missing prerequisite and requested
it before substantive review. An exact prerequisite and recovery route prevented
guessing which “latest files” were the delivery.

For small work, a commit, short file list, and a message are enough. A separate
manifest is useful when versions and access distinctions actually matter.

## The publication hold

The local summary was accepted with qualifications. A later publication plan
could not establish its required capture completeness.

A page snapshot reported that it was not truncated, but the inspected tool
contracts did not prove coverage of every intended subtree or explicit reporting
of unsupported/omitted content. This did not demonstrate an actual missing
subtree. Separately, a database capture contained 12 of 54 rows with another
cursor available.

The owner retained the completeness requirement and held the plan on November 6.
The hold was still carried in the November 10 acceptance record. Local package
checks did not supply the missing destination evidence.

| Item | Recorded state at this cutoff |
| --- | --- |
| Technical diagnostic | Closed with qualifications |
| Local summary | Accepted with qualifications |
| Diagnostic publication to Notion | Pending, on hold |
| Successor retrieval checkpoint and navigation | Pending under the held plan |
| Earlier 416-source publication | Retained at its own cutoff |

Seventeen intended additions did not establish verified coverage of 433 sources.
The next useful decision concerned a supported capture method or an agreed
alternative scope. Repeating local checks could not resolve that question.

This is a worked application of destination separation already present in the
public templates, not a newly discovered principle or a claim about every
publication tool.

## Preserve evidence when displaying it

A later review assignment added explicit output rules, including:

> Do not rerun a judging command simply to recover display.

A small adaptation is to save complete results before displaying a summary,
read long required documents in ordered windows, and recover clipped output
from the saved result. A summary is not proof of a full read. Report unknown
wrapper overhead honestly. The original numerical output caps belonged to that
environment and are not universal recommendations.

## What to adapt

Define routine ownership and material decisions, identify phase prerequisites,
and attach qualifications to each claim. Track only the destinations you use.
The coordination route was exercised; these records do not measure time saved
or prove that more documents improve every project.
